# 02 · The first documents

- **Date:** 9 October 2026
- **Status:** done

## Goal

Write down what we build, why, in which order, and how we measure it, before any code exists.

## Approach

Two documents with two different jobs, plus this backlog.

| File | Job | Read |
|---|---|---|
| `CLAUDE.md` | The rules, as orders: hard constraints with fixed numbers, the build order with its gates, what to ask the owner | In every session, automatically |
| `docs/blueprint.md` | The reasoning: the problem, the card, the five steps, the Hedera part, the tech stack with reasons, the website, the tests, the calendar | When a task needs it |
| `backlog/` | The history: steps, decisions, lessons, open questions | At the start of a session |
| `README.md` | A short and honest front page | By visitors |
| `.env.example`, `.gitignore` | The names of the secret values, and what never enters git | By whoever sets the project up |

There is no separate plan, to-do or status file. A second plan in the repository drifts away from the first one.

## Results

- 16 hard constraints, 9 launch gates, 2 build gates.
- A blueprint of 20 sections (§0 to §19), with fixed section numbers.
- 4 tests described, with proposed pass marks. They were fixed later the same day: see [entry 03](03-answers-and-terms.md).
- 6 screens described.

## What this does not prove

Nothing was built or run. Every choice in the tech stack is still a plan until Gate A.
