# Test 3, run of October 2026: the Hedera IDs and the proof rule

This is the short report of Test 3 (design 13.4). It answers three questions. Does the tool find the Hedera IDs that a page and the README of its code name? Does it add IDs that are not the project's? Does it give each ID the status that a careful reader gives it? The numbers come from `evals/results/20261018T185311Z-test3.json`. The rules are in `guideline.md`.

## What was tested

- **50 project pages** of ETHGlobal's showcase and the READMEs of their code, drawn from three groups fixed before the draw: 15 pages where the tool found an ID on the page, 20 where it found one in the README only, and 15 where it found none.
- **A second reader,** a language model that is not part of the tool (as for the second grader of Test 1), read every page in full and every README around each string shaped like an ID, and wrote down each ID of the project with its network and its kind. The public mirror node was asked about each one with plain HTTP, not with the tool's code, and the reader gave each ID a status by the table of design 7.2.
- **156 IDs on 34 pages:** 17 on the pages and 139 in the READMEs. 16 pages name none.
- **The tool's work:** the IDs that its parser found and the statuses that its check gave, read from its tables.
- **Three planted IDs,** which stand in no text, were counted as missed, as they must be.

## The numbers

| Number | Result | Range | Pass mark (design 13.6) | |
|---|---|---|---|---|
| Found: the reader's IDs that the tool found in the same place | 156 of 156 (100%) | 100% to 100% | at least 95% | met |
| Invented: the tool's IDs that the reader does not count | 22 of 178 (12.4%) | 3.9% to 23.3% | at most 2% | **not met** |
| Status: the IDs that both found, with the same status | 148 of 156 (94.9%) | 89.2% to 98.7% | at least 90% | met |

A range says how far a number moves when the pages are drawn again (design 13.1). As design 13.6 says, a mark is not moved after a run.

## What the tool adds

The 22 IDs that the tool counts and the reader does not are of three kinds.

- **10 accounts and transactions of a local network.** One project runs its own copy of a Hedera network on the computer, and its page and README name the accounts of that copy. The tool cannot tell a local network from the ledger, so it asks the ledger about the same numbers, which are other things there.
- **5 example values,** such as 0.0.123456 or 0.0.12345, given to show the form of an ID or inside a sample output. Two of them exist on the ledger, and the tool gave them "proof found".
- **7 scheduled transactions.** The guideline counts accounts, tokens, topics, contracts and transactions; a schedule is none of these, so the test counts these seven as added. They are real things on the ledger. The tool's check does not ask for schedules, so it says "not found" for each.

## Where the statuses differ

8 of the 156 IDs got another status from the tool.

- **5 times the kind word:** the tool took the kind from a neighbouring line or row of a table, where another thing is named (a topic, an account, a token). So a thing of the right kind looked like another kind to it, and where no network is named, the thing of the same number on the main network decided its status.
- **2 times a shared token that moved inside the window:** the tool looks at the day the token was made, two years earlier, and says that the dates do not fit. The reader counts the move that a transaction of the set shows inside the window.
- **Once a contract call with no kind word:** the code calls the ID as a contract, and the ledger has an account. The reader judged it another kind of thing; the tool, with no kind word, judged its dates.

## The limits of this test

- **Two shapes are outside the guideline:** schedules, and a transaction written with a dash and then a dot. Neither was counted. The tool does not read them as such either.
- **The moves of a token** are not among the facts that the test reads. A move counts when a transaction named in the set shows it.
- **The mirror node of the test network** lists the transactions of a very busy account only from recent days. For such an account the one more question of design 7.2 was asked: did it take part in a transaction inside the window?
- **The reader is a model, not a person.** The guideline speaks of a person. No person checked the reader's work, so its own mistakes are not measured here.
- **Ten READMEs were not read blind.** A first run used a reading aid that cut most READMEs at their first block of code. That run is not counted, and its file is kept apart. Its output showed part of the tool's list for ten projects, so the second, full reading of those ten READMEs came after seeing part of the tool's answer.
- It does not show that an ID belongs to the team that names it.

## What it means

The tool finds every ID that the reader finds, and its status agrees 95 times in 100. It counts too much: the IDs of local networks, example values, and schedules. The changes that would matter most: leave out values that a text gives as an example, read the words that put an ID on a local network, and ask for a schedule as a kind of its own.

## 22 October 2026: the run after three changes of the reader

The three changes named above were made on 22 October 2026, and the test ran again on the same 50 pages, with the same answers of the reader (`evals/results/20261022T094640Z-test3.json`). The guideline and the pass marks did not change.

| Number | Result | Range | Pass mark (design 13.6) | |
|---|---|---|---|---|
| Found | 156 of 156 (100%) | 100% to 100% | at least 95% | met |
| Invented | 8 of 164 (4.9%) | 1.2% to 8.8% | at most 2% | **not met** |
| Status | 148 of 156 (94.9%) | 89.2% to 98.7% | at least 90% | met |

- **Example values.** A number whose digits count up or down, such as 0.0.12345 or 0.0.54321, is no longer an ID. In the whole collection there were 36 of them, and each one, read in its place, was an example.
- **A local network.** The default accounts of Hedera's local node, 0.0.1002 to 0.0.1031, are no longer IDs, and neither are the transactions they paid. One number of the same local network stays: 0.0.1033, made after the default accounts.
- **Schedules.** A link to a schedule on HashScan, or the word "schedule" right before an ID, names a scheduled transaction, and the check asks the mirror node about it as one. The 7 schedules now get "proof found". They still count as invented, because the guideline counts no schedule, and a guideline is not changed after a run.

A first version of the third change took "schedule" anywhere near an ID. On these 50 pages it turned one status wrong, a token whose fee schedule was named after its ID, so it was narrowed before this run. That run is not kept in the repository.

The tool still finds every ID that the reader finds, and agrees on 95 statuses in 100. What it adds now is one number of a local network and seven schedules.

## 22 October 2026, later: schedules count as IDs

Later the same day, the maintainer decided that a scheduled transaction counts as an ID of a project, and the guideline got a dated last section that says how a schedule is checked. This changes the test after a run, so both results are kept: the one above, under the first guideline, and this one. The pass marks did not move, and the tool's answers are the same as in the run above.

The second reader read the 50 pages again for schedules: every HashScan link with `/schedule/`, and every ID a few words before or after the word "schedule". This found 7 schedules on 4 pages, the same 7 that the tool found, and no other. Each of them ran inside the window of its event, so its status by hand is "proof found" (`evals/results/20261022T110121Z-test3.json`).

| Number | Result | Range | Pass mark (design 13.6) | |
|---|---|---|---|---|
| Found | 163 of 163 (100%) | 100% to 100% | at least 95% | met |
| Invented | 1 of 164 (0.6%) | 0% to 2.1% | at most 2% | met |
| Status | 154 of 163 (94.5%) | 89.1% to 98.2% | at least 90% | met |

- **The one ID that the tool still adds** is 0.0.1033 of a local network, described above.
- **One schedule has another status.** The tool takes the word "contract" a few words after it as its kind, and says "another kind". The guideline takes only the word right before the ID or right after it: here the name of a file, and a word that is not a kind. So by hand the kind is open, and the status is "proof found".
- **The range of the invented IDs** reaches 2.1%, just above the mark. If other pages were drawn, the number could be a little over the mark. As in every test, the mark is judged on the number itself.

Under the guideline as it stands now, all three numbers meet their marks. Under the first guideline, the share of invented IDs does not.
